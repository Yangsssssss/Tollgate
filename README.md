# llm-gateway

面向多租户的大模型 API 网关：统一接入 OpenAI 兼容协议，在多渠道之间做**智能调度**，并对每次调用做**token 级计量**与计费。

核心不是"转发"，而是**在多个上游渠道之间做出最优选择并扛住局部故障**。

## 设计目标

- **协议统一**：对外只暴露 OpenAI 兼容协议（`/v1/chat/completions`），上游可以是任意厂商
- **调度优先**：渠道选择、限流、熔断、故障转移、密钥轮换构成调度内核
- **计量精确**：prompt / completion token 双口径采集，为计费提供可信数据源
- **可演进**：控制平面与数据平面分离，后续 Agent 调度、MCP 工具调用以插件形式接入

## 模块划分

| 模块 | 职责 |
|---|---|
| `gateway-common` | 领域模型、枚举、统一异常、工具类 |
| `gateway-upstream` | 上游适配器 SPI + 各厂商协议实现 |
| `gateway-core` | 调度内核：路由策略、限流、熔断、Key 池、请求编排 |
| `gateway-metering` | 用量采集、token 统计、事件落库、计费钩子 |
| `gateway-app` | Spring Boot 启动、WebFlux 入口、管理 API、Flyway 迁移 |

## 调度内核

一次请求的调度链：

1. **候选集筛选** —— 模型别名 → 可用渠道列表，剔除禁用渠道、不支持的模型、无可用密钥、熔断打开的渠道
2. **限流预检** —— 租户级 RPM/TPM、渠道级并发，超出则快速失败或降级
3. **渠道选择** —— 优先级分层 + 层内平滑加权轮询，可切换成本优先策略
4. **转发执行** —— 取密钥、构造上游请求、SSE 流式透传
5. **故障转移** —— 超时 / 5xx / 429 触发同层重试，记录失败并驱动熔断器状态机
6. **计量落库** —— 旁路嗅探响应 usage，无 usage 时按字符估算，异步批量写入

熔断器三态：`CLOSED → (失败率超阈值) → OPEN → (冷却期后) → HALF_OPEN → (探测成功) → CLOSED`

## 数据模型

| 表 | 说明 |
|---|---|
| `tenant` | 租户，隔离维度 |
| `api_key` | 对外下发的虚拟密钥，绑定租户与额度 |
| `provider` | 上游厂商定义（openai / anthropic / deepseek ...） |
| `channel` | 渠道 = 厂商账号 + Base URL + 权重 + 优先级 + 状态 |
| `channel_key` | 渠道路由下的上游密钥池 |
| `model` | 模型定义与别名、上下文长度、单价 |
| `model_route` | 模型 × 渠道 的可用映射（含该组合下的权重覆盖） |
| `request_log` | 单次调用明细：链路 ID、耗时、状态、渠道、重试次数 |
| `usage_record` | 计量明细：prompt / completion token、成本 |
