# Tollgate

> 大模型收费站 —— 统一的 API 闸口，按渠道分流，按 token 计费。

一个面向多租户的大模型 API 网关：对外只暴露 OpenAI 兼容协议，对内把每次请求分发到最合适的上游渠道，并在出口处完成 token 级计量与计费。

这个项目不解决"能不能转发"，解决的是**几十条渠道、上百个密钥、随时挂掉的上游之间，如何稳定地选一条路并把账算准**。

## 核心设计

| 关注点 | 做法 |
|---|---|
| 协议统一 | 对外 `/v1/chat/completions`，上游可为任意厂商，适配器负责转换 |
| 调度优先 | 候选集筛选 → 限流 → 加权选道 → 转发 → 故障转移 |
| 热路径零查库 | 渠道状态、密钥、限流计数全走内存 + Redis，DB 只在控制面和异步落账 |
| 计量可信 | 优先取上游返回的真实 usage，缺失时按字符估算并标记来源 |
| 可演进 | 控制面 / 数据面分离，Agent 调度与 MCP 以新模块接入 |

## 术语表

整套代码和文档统一使用这套词汇，避免同一个东西三种叫法：

| 术语 | 含义 |
|---|---|
| **Lane**（车道） | 一个上游渠道：厂商 + Base URL + 密钥池 + 权重 + 优先级 |
| **Toll**（过路费） | 一次调用的计量记录：token 数 + 成本 |
| **Tariff**（费率表） | 模型定价规则，按输入/输出 token 分别计价 |
| **Pass**（通行证） | 租户的预付费额度账户 |
| **Gate**（闸口） | 请求入口，负责鉴权与协议校验 |
| **LaneClosed** | 车道熔断关闭，暂停分配流量 |
| **ToolBooth** | V3 预留：MCP 工具调用的独立计量通道 |

## 模块

| 模块 | 职责 |
|---|---|
| `tollgate-common` | 领域模型、错误码、通用工具 |
| `tollgate-upstream` | 上游适配器 SPI 与各厂商实现 |
| `tollgate-core` | 调度内核：候选集、限流、选道、熔断、密钥池 |
| `tollgate-metering` | 用量采集、token 统计、异步落账 |
| `tollgate-app` | Spring Boot 启动、数据面入口、控制面 API、DB 迁移 |

## 一次请求的调度链

```
1. Gate        解析虚拟密钥 → 定位租户 → 额度与状态校验
2. Candidate   模型别名展开 → 剔除禁用/无密钥/熔断中的车道
3. RateLimit   租户 RPM/TPM 与车道并发预检，超限快速失败
4. Dispatch    优先级分层 → 层内平滑加权轮询 → 选出本次车道与密钥
5. Forward     构造上游请求 → SSE 流式透传 → 旁路嗅探 usage
6. Failover    超时/5xx/429 → 同层换道重试 → 驱动熔断器状态机
7. Toll        组装计量记录 → 入队 → 批量落库
```

熔断器状态机：`CLOSED →(失败率超阈)→ OPEN →(冷却)→ HALF_OPEN →(探测成功)→ CLOSED`

## 数据模型

| 表 | 说明 |
|---|---|
| `tenant` | 租户，隔离维度 |
| `api_key` | 对外虚拟密钥，绑定租户 |
| `provider` | 上游厂商定义 |
| `lane` | 车道：厂商账号 + Base URL + 权重 + 优先级 + 状态 |
| `lane_key` | 车道下的上游密钥池 |
| `model` | 模型定义、别名、上下文长度 |
| `model_lane` | 模型 × 车道 可用映射，支持该组合下的权重覆盖 |
| `tariff` | 费率表：输入/输出单价（V2） |
| `request_log` | 调用明细：链路 ID、耗时、状态、车道、重试次数 |
| `toll_record` | 计量明细：prompt/completion token、成本 |

## 技术栈

Java 21 · Spring Boot 3.5 · WebFlux (Reactor Netty) · PostgreSQL · Flyway · Redis

热路径全异步非阻塞；控制面与落账走 JDBC + 虚拟线程，不为了"纯响应式"牺牲可维护性。
